# 学生工作台重构设计规格

## 背景

第一阶段已经完成 Lumina 响应式课表工作台。当前学生页面仍采用两个纵向堆叠的普通卡片：

- 点击学生卡片会立即打开编辑弹窗，无法先查看学生信息。
- 学生详情 API 已提供月收入、月课时、课程数、请假数和模板数量，但前端没有使用。
- 课表模板仅以简单列表呈现，重复周期和生效范围不够直观。
- 手机端与桌面端使用相同信息结构，缺少针对单手操作的层次。

第二阶段采用“学生工作台重构”方案，在不修改后端接口和数据库的前提下，提升学生资料与固定课表的浏览、选择和编辑效率。

## 目标

- 将学生页面更新为与课表工作台一致的 Lumina 视觉体系。
- 将“选择学生”和“编辑学生”拆分为两个明确动作。
- 使用现有学生详情接口展示月度业务数据。
- 将周课表模板改为易扫描的星期时间卡片。
- 为桌面和手机分别组织信息层级。
- 保留新增、编辑、归档、价格重算、模板创建、模板更新和模板删除能力。

## 非目标

- 不新增学生标签、欠费记录、沟通记录或跟进提醒。
- 不增加批量归档、批量调价等批量操作。
- 不修改学生、课程或课表模板的数据模型。
- 不重构数据统计和设置页面。

## 页面结构

### 桌面端

学生页面采用两栏工作台布局：

1. 左栏为学生目录，宽度约 320px：
   - 页面标题、学生总数和新增学生按钮。
   - 姓名或电话号码搜索框。
   - 学生卡片列表。
   - 卡片显示头像色、姓名、单价、电话和状态。
   - 点击卡片只切换选中学生。
2. 右栏为选中学生工作区：
   - 学生身份摘要、编辑入口和归档状态。
   - 本月收入、课时、课程数、请假数和模板数量。
   - 联系电话与备注。
   - 周课表模板区域。

当没有学生时，页面显示新增引导；当尚未选中学生时，右栏显示选择引导。

### 手机端

- 页面顶部显示标题、学生数量和新增按钮。
- 搜索框固定在学生目录顶部。
- 学生列表使用横向紧凑卡片。
- 选中学生后，在列表下方显示学生摘要、月度指标和模板。
- 页面自动滚动不是必要行为，避免打断用户当前位置。
- 编辑与新增按钮的触控区域不小于 44px。
- 继续使用全屏遮罩加底部表单面板完成资料和模板编辑。

## 核心交互

### 学生选择与编辑

- 点击学生卡片仅发出 `select-student`，更新 `selectedStudentId`。
- 卡片和详情区均提供独立“编辑”按钮，发出 `edit-student`。
- 新增学生成功后刷新学生列表；如果返回的新学生 ID 不可直接获得，则保持当前选中项，不做猜测性切换。
- 当前选中学生从列表消失时，自动选择新的第一位学生；列表为空时清空选择。

### 搜索

- 搜索在前端本地完成，不增加 API 请求。
- 匹配学生姓名和电话号码，忽略大小写及首尾空格。
- 无匹配结果时显示“没有找到匹配的学生”，并保留清除搜索入口。

### 学生详情

- 选中学生后调用 `GET /students/{id}`。
- 加载期间显示局部骨架或明确加载提示，不阻塞学生目录。
- 请求失败时显示局部错误和重试按钮。
- 详情数据用于展示：
  - 本月预计收入。
  - 本月课时。
  - 本月课程数。
  - 本月请假数。
  - 固定模板数。

### 课表模板

- 模板按 `day_of_week`、`start_time` 排序。
- 每张卡片显示星期、开始时间、课时长度、重复周期和生效范围。
- 重复周期文案：
  - `1`：每周。
  - `2`：隔周。
  - `3`：每 3 周。
  - `4`：每 4 周。
- 点击模板卡片或编辑按钮打开模板编辑面板。
- 未选中学生时禁用新增模板入口并显示引导。
- 没有模板时显示空状态与新增模板按钮。

## 组件边界

### `StudentsPanel.vue`

负责学生目录：

- 搜索和过滤。
- 学生卡片与选中状态。
- 新增、选择、编辑事件。
- 不请求详情，不管理模板。

### `StudentOverview.vue`

负责选中学生详情：

- 接收 `StudentDetail | null`。
- 展示身份、联系方式、备注和月度指标。
- 发出编辑和重试事件。
- 不直接调用 API。

### `TemplateManager.vue`

负责选中学生的模板展示：

- 模板排序和重复周期文案。
- 模板空状态。
- 新增与编辑事件。
- 不负责学生选择。

### `DashboardPage.vue`

负责数据编排：

- 保存 `selectedStudentId` 和 `selectedStudentDetail`。
- 在选中学生变化时并行或连续加载详情与模板。
- 控制学生、模板表单开关。
- 保持现有课表和统计数据加载逻辑不变。

### `studentWorkspace.ts`

提供可测试的纯函数：

- 学生搜索过滤。
- 选中学生 ID 归一化。
- 模板排序。
- 重复周期格式化。

## 数据流

1. Dashboard 初始加载活动学生列表。
2. 如果当前没有有效选择且列表非空，选择第一位学生。
3. `selectedStudentId` 变化时：
   - 清空旧的局部错误。
   - 加载 `studentsApi.get(id)`。
   - 加载 `templatesApi.list(id)`。
4. 两个请求分别维护错误状态；其中一个失败不应清空另一个的成功数据。
5. 学生编辑成功后重新加载学生列表和当前学生详情。
6. 模板变更成功后只重新加载当前学生的模板和学生详情中的模板数量。

## 状态与错误处理

- 学生列表加载失败：使用页面现有全局数据错误提示。
- 学生详情失败：右栏显示“学生详情加载失败”与重试按钮。
- 模板加载失败：模板区域显示“课表模板加载失败”与重试按钮。
- 搜索无结果：不视为错误。
- 表单提交期间禁用提交按钮，防止重复请求。
- 归档与删除继续遵循现有后端业务规则。

## 视觉规范

- 延续第一阶段的紫粉柔光背景、渐变主按钮和半透明卡片。
- 学生个人色只用于头像、时间轴或小面积强调，不覆盖主要文本背景。
- 选中学生卡片使用紫粉浅色底、细描边和明确的 `aria-current` 状态。
- 指标卡使用统一数字层级，不为每个指标分配无关的高饱和颜色。
- 模板卡以星期和时间作为第一视觉层级，以重复周期作为次级标签。
- 兼容现有暗色模式。

## 可访问性

- 搜索框具有可见标签或 `aria-label`。
- 学生卡片使用按钮语义。
- 编辑按钮必须阻止触发卡片选择后的重复行为。
- 所有纯图标按钮提供可访问名称。
- 键盘焦点状态使用现有全局焦点环。
- 状态不能只依赖颜色表达。

## 测试

### 单元测试

- 学生姓名和电话号码过滤。
- 空搜索返回全部学生。
- 当前选择失效时回退到第一位学生。
- 模板按星期和时间排序。
- 重复周期文案转换。

### 组件测试

- 点击学生卡片发出选择事件，不发出编辑事件。
- 点击独立编辑按钮发出编辑事件。
- 搜索无结果显示空状态。
- 学生详情正确显示月度指标和空联系方式。
- 模板卡正确显示重复周期和生效范围。
- 详情及模板错误状态可以触发重试。

### 集成与浏览器验收

- `npm test` 与 `npm run build` 通过。
- 1440×900 下双栏布局无横向溢出。

- 独立编辑入口可以打开学生表单。
- 新增和编辑模板入口可用。
